# Torrent Igruha → Hydra Launcher source

Скрипт собирает раздачи с `itorrents-igruha` и генерирует **igruha.json** — источник загрузок для [Hydra Launcher](https://github.com/hydralauncher/hydra) (формат: `{ name, downloads: [{ title, uris, uploadDate, fileSize }] }`).

Magnet-ссылки строятся из скачанных `.torrent`-файлов (infohash v1), поэтому всё работает напрямую в Hydra Launcher без сторонних расширений.

## Особенности источника

- **Декодирование кодировки**: Сайт работает на `windows-1251`, скрипт корректно декодирует разметку без повреждения кириллицы.
- **Прямой расчет infohash**: Скачивает `.torrent` через эндпоинт CMS DLE `engine/download.php?id=...`, нативно парсит bencode-словарь `info` и строит валидную magnet-ссылку с популярными трекерами (`opentor`, `opentrackr`, `demonii` и др.).
- **Многоуровневый кэш**: При повторных запусках уже полученные раздачи берутся из `.cache/downloads.json` мгновенно, не нагружая сайт.
- **Поддержка карты сайта (Sitemap)**: Позволяет собирать как только новинки (`sitemap-fresh.xml`), так и весь архив каталога (~25 000+ игр из `sitemap-games-*.xml`).
- **Автоматическая проверка обновлений**: Режим `--check-updates` сверяет отпечатки (размер/дата/название) и перекачивает magnet при обновлении репака.

## Файлы

| Файл | Назначение |
|---|---|
| `scrape.mjs` | скрапер: обходит страницы сайта, скачивает `.torrent`, строит magnet и пишет `igruha.json` |
| `igruha.json` | итоговый источник для Hydra Launcher |
| `.cache/downloads.json` | кэш «страница игры → magnet»: повторные запуски не качают торренты заново |
| `publish.sh` | скрипт безопасной публикации результатов в git с защитой от гонки коммитов |
| `.github/workflows/update.yml` | автозапуск по расписанию в GitHub Actions + коммит обновлений |

## Запуск

```bash
node scrape.mjs                      # последние 3 страницы каталога (по умолчанию)
node scrape.mjs --pages 10           # 10 страниц каталога
node scrape.mjs --fresh              # новинки через sitemap-fresh.xml (~1400 игр)
node scrape.mjs --fresh --limit 500  # до 500 новых игр из sitemap-fresh
node scrape.mjs --all                # ВЕСЬ каталог через все sitemap (~25 000+ игр)
node scrape.mjs --all --limit 2500   # порция до 2500 новых игр из архива
node scrape.mjs --check-updates --updates-limit 1500 --refresh # проверка обновлений версий в кэше
node scrape.mjs --time-limit 60      # мягкий лимит: остановиться через 60 минут и сохранить результат
```

### Параметры запуска

| Флаг | Описание |
|---|---|
| `--pages N` | Количество страниц каталога для обхода (по умолчанию: 3) |
| `--fresh` | Обход свежих релизов из `sitemap-fresh.xml` |
| `--all` | Полный обход всего сайта из всех sitemap |
| `--limit N` | Максимальное количество **новых** добавленных игр за запуск |
| `--check-updates` | Проверка закэшированных игр на изменение версии на сайте |
| `--refresh` | Разрешает перекачивать торренты при обнаружении обновлений |
| `--updates-limit N` | Лимит проверяемых игр при `--check-updates` |
| `--time-limit N` | Мягкий лимит времени работы в минутах (сохраняет кэш и JSON перед выходом) |
| `--domain URL` | Базовый URL зеркала (по умолчанию: `https://itorrents-igruha.net`) |

## Как подключить в Hydra

1. Создайте репозиторий на GitHub и запушьте эти файлы.
2. Включите GitHub Actions (вкладка **Actions** → разрешить workflows) — файл будет обновляться раз в сутки автоматически.
3. Ссылка на источник для Hydra:
   ```
   https://raw.githubusercontent.com/<ВАШ_ПОЛЬЗОВАТЕЛЬ>/<РЕПОЗИТОРИЙ>/main/igruha.json
   ```
4. В Hydra Launcher: **Настройки → Источники загрузки → Добавить (+)** → вставьте ссылку.

## Автообновление через GitHub Actions

Workflow `update.yml` запускается раз в сутки в 03:00 UTC (или вручную через `workflow_dispatch`). Он последовательно выполняет:
1. `news` — свежие игры с каталога (~30 мин timeout)
2. `fresh` — свежие игры из sitemap-fresh (~60 мин timeout)
3. `catalog` — порция общего архива (~300 мин timeout)
4. `check-updates` — проверка обновленных версий (~180 мин timeout)

Каждый шаг коммитит результат через `publish.sh` с автоматическим rebase при параллельных пушах.
